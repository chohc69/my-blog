## 1. 개요와 게임 규칙

### 개요
**머지 타일**은 4×4 격자 위의 숫자 타일을 한 방향으로 밀어, 같은 숫자끼리 부딪히면 하나로 합쳐지는 슬라이드-합치기 퍼즐입니다.
정해진 "승리 숫자"를 향해 달리는 대신, 판이 막힐 때까지 얼마나 높은 타일을 만들고 점수를 쌓는지를 겨루는 **끝없는 기록 도전형** 게임입니다.
블로그(my-blog)의 인디고 계열 테마와 다크 모드를 그대로 따르며, 순수 HTML/CSS/JS(ES Modules)로 `apps/merge-tiles/` 안에 자체 완결됩니다.

> 독자성 원칙: UI 어디에도 "2048"이라는 이름·로고·문구를 쓰지 않고, 기존 게임의 베이지/주황 배색과 화면 구성을 따르지 않습니다.
> 타일 값으로 2048이라는 숫자가 나오는 것은 산술상 자연스러우나, 이를 특별한 목표나 문구로 강조하지 않습니다.

### 규칙
1. 시작 시 빈 칸 중 임의의 2곳에 타일이 생깁니다.
2. 방향(← → ↑ ↓)을 입력하면 모든 타일이 그 방향 끝까지 미끄러집니다.
3. 이동 경로에서 **같은 값의 타일 두 개가 만나면 하나로 합쳐지고 값은 두 배**가 됩니다.
   - 한 번의 이동에서 이미 합쳐져 생긴 타일은 같은 이동 안에서 다시 합쳐지지 않습니다. (예: `[2,2,4,_]` ← → `[4,4,_,_]`, `[8,_,_,_]`이 아님)
   - 같은 값이 3개 이상 연속이면 **이동 방향 쪽부터** 짝을 지어 합칩니다. (예: `[2,2,2,_]` ← → `[4,2,_,_]`, → 방향이면 `[_,_,2,4]`)
4. 이동으로 판이 실제로 바뀐 경우에만 빈 칸 1곳에 새 타일(2 또는 4)이 생깁니다. 아무 변화가 없는 입력은 무시합니다(턴 소모 없음).
5. 합칠 때마다 **합쳐진 결과 값만큼 점수**를 얻습니다.
6. 빈 칸이 없고 상하좌우로 인접한 같은 값도 없으면 **게임 오버**입니다.

### 승리 조건 대신: 단계별 메달 (결정 사항)
고정 승리 조건(특정 숫자 도달 시 "승리!")을 두지 않고, **최고 타일 단계에 따라 메달**을 줍니다.

| 최고 타일 | 메달 | 표시 |
|---|---|---|
| 128 | 브론즈 | 동 |
| 256 | 실버 | 은 |
| 512 | 골드 | 금 |
| 1024 | 플래티넘 | 백금 |
| 그 이상(값이 두 배가 될 때마다) | 마스터 ★, ★★ … | 별 개수로 누적 |

**이유**
- 특정 숫자 도달 = 승리 화면은 원작 게임의 상징적 구성이라, 이를 피하는 것이 독자성 요구에 부합합니다.
- 메달은 초보자에게 128~256에서 빠른 성취감을, 숙련자에게는 끝없는 상위 목표(마스터 별)를 줘 동기 곡선이 완만합니다.
- 게임이 "이기면 끝"이 아니므로 흐름이 끊기지 않고, 점수판·상위 기록과 자연스럽게 연결됩니다.
- 새 메달을 처음 얻는 순간 보드 위에 짧은 토스트("골드 메달 달성!")를 띄우되 게임을 멈추지 않습니다.

## 2. 기능 목록

### 필수
- [ ] 4×4 격자, 시작 타일 2개, 이동 후 새 타일 1개 (2: 90%, 4: 10%)
- [ ] 조작: 방향키 + WASD (키보드), 스와이프 (터치/펜/마우스 드래그, Pointer Events)
- [ ] 스와이프 중 페이지 스크롤 방지 (보드에 `touch-action: none`), 방향키 입력 시 `preventDefault`로 페이지 스크롤 방지
- [ ] 점수판: 현재 점수, 최고 점수(`localStorage`, 모든 접근 `try/catch`)
- [ ] 점수 증가 시 "+8" 같은 플로팅 표시
- [ ] 상위 기록 목록 Top 5 (점수, 최고 타일, 날짜)
- [ ] 새 게임 버튼 (진행 중 점수가 있으면 확인 대화 — 네이티브 `<dialog>` 사용)
- [ ] 게임 오버 감지 + 보드 위 오버레이 (최종 점수, 최고 타일, 메달, "다시 하기" 버튼)
- [ ] 단계별 메달 표시 (현재 게임에서 얻은 메달)
- [ ] 타일 이동(슬라이드) / 합치기(팝) / 생성(등장) 애니메이션, `prefers-reduced-motion` 시 최소화
- [ ] 라이트/다크 모드 (블로그 `theme` 키 공유, 시스템 설정 폴백)
- [ ] 375px 폭에서 가로 스크롤 없음

### 선택 (우선순위 순, 1·2는 이번 Build에 포함 권장)
1. **되돌리기 — 게임당 1회**: 직전 한 수만 되돌림. 사용 후 버튼 비활성화, 남은 횟수 표시("되돌리기 1"). 게임 오버 상태에서도 사용 가능(오버레이 닫고 복귀).
2. **진행 중 게임 이어하기**: 페이지를 새로고침해도 판·점수·되돌리기 잔여 횟수를 복원.
3. 키보드 단축키 `N`(새 게임), `U` / `Ctrl+Z`(되돌리기).
4. 임베드 모드(`?embed=1`): 헤더·기록 목록을 숨긴 콤팩트 화면 (8장 Embed 계획에서 사용).

### 범위 밖
- 격자 크기 변경, 온라인 랭킹, 사운드, 외부 라이브러리.

## 5. 핵심 로직 설계

### 5.1 상태 구조 (`game.js`)
```js
// 게임 상태 (직렬화 가능한 순수 객체)
{
  size: 4,
  cells: [/* 길이 16, row-major. 각 칸은 null 또는 Tile */],
  score: 0,
  maxTile: 2,
  undoLeft: 1,          // 게임당 되돌리기 남은 횟수
  over: false,
  nextId: 3,            // 타일 고유 id 발급용 (애니메이션 시 DOM 요소 재사용 키)
  startedAt: '2026-11-28T09:00:00.000Z',
}

// Tile
{ id: 7, value: 16 }
```
- 위치는 `cells` 인덱스(`row * 4 + col`)로만 표현 → 상태가 한 곳에만 있도록 유지.
- **되돌리기 스냅샷**은 `game` 상태 밖(`main.js`)에서 `structuredClone(state)` 1개만 보관. 되돌리기 시 스냅샷으로 교체하고 `undoLeft`는 차감된 값을 유지.

### 5.2 이동/합치기 알고리즘
`move(state, direction, rng) → { state, moved, gained, moves, merges, spawned }` — 입력 상태를 변경하지 않고 새 상태를 반환(불변).

1. **라인 추출**: 방향에 따라 4개의 라인을 "이동 방향 쪽이 앞"이 되도록 인덱스 배열로 만든다.
   - left: 각 행 `[c0, c1, c2, c3]` / right: 각 행 `[c3, c2, c1, c0]`
   - up: 각 열 `[r0, r1, r2, r3]` / down: 각 열 `[r3, r2, r1, r0]`
2. **라인 처리** (앞에서부터 한 번 순회):
   ```
   target = 0; lastMergeable = null
   for i in 0..3:
     tile = line[i]; if 없음 → continue
     if lastMergeable && lastMergeable.value == tile.value:
        → 합치기: 새 타일 {id: nextId++, value: tile.value*2}을 lastMergeable 자리(target-1)에 배치
          merges.push({ from: [lastMergeable.id, tile.id], to: target-1, newId, value })
          moves.push({ id: tile.id, to: target-1 })   // 흡수되는 타일도 목적지까지 미끄러진 뒤 사라짐
          gained += value*2; lastMergeable = null      // 같은 이동에서 재합치기 금지
     else:
        → 이동: tile을 target 자리에 배치, moves.push({ id, from: i, to: target })
          lastMergeable = 배치된 tile; target++
   ```
3. 모든 라인 처리 후 이전과 셀 배치가 하나라도 달라졌으면 `moved = true`.
4. `moved`이면: `score += gained`, `maxTile` 갱신, `spawn()` 1회, `isGameOver()`로 `over` 갱신.
5. `moved`가 아니면 원래 상태를 그대로 반환(새 타일 없음, 턴 소모 없음).

**인덱스 변환 하나로 4방향을 처리**하므로 방향별 코드 중복이 없습니다.

### 5.3 새 타일 생성
- `spawn(state, rng = Math.random)`: 빈 칸 목록에서 `Math.floor(rng() * n)`으로 하나 선택, 값은 `rng() < 0.9 ? 2 : 4`.
- 빈 칸이 없으면 아무것도 하지 않음(이동이 일어났다면 최소 1칸은 비어 있으므로 정상 흐름에선 발생하지 않음).
- 새 게임: 빈 판 + `spawn` 2회.
- `rng`를 인자로 받아 테스트에서 고정 시퀀스 주입 가능.

### 5.4 게임 오버 판정
```
isGameOver(cells):
  빈 칸이 하나라도 있으면 false
  모든 칸에 대해 오른쪽 이웃 또는 아래 이웃과 값이 같으면 false
  그 외 true
```
- 매 이동 후 1회 실행(O(16)), 오버 시 입력 무시 + 오버레이 표시 + 기록 저장.

### 5.5 점수 계산과 기록
- 합칠 때 결과 값을 더함 (`2+2 → +4`, `64+64 → +128`).
- **최고 점수**: 점수가 최고를 넘는 순간 실시간 갱신·저장. 되돌리기로 점수가 내려가도 최고 점수는 내리지 않음.
- **상위 기록 Top 5**: 게임 오버 시, 또는 점수 > 0인 상태에서 "새 게임"을 확정할 때 `{ score, maxTile, date: 'YYYY-MM-DD' }`를 추가하고 점수 내림차순 정렬 후 5개만 유지. 이번 기록이 목록에 들면 해당 행을 강조("새 기록").
- **메달**: `medalFor(maxTile)` — 128→bronze, 256→silver, 512→gold, 1024→platinum, 2048 이상은 `master` + 별 개수 `log2(maxTile) - 10`.

### 5.6 저장소 (`storage.js`)
| 키 | 값 | 비고 |
|---|---|---|
| `merge-tiles:best` | 숫자 | 최고 점수 |
| `merge-tiles:records` | `[{score, maxTile, date}]` 최대 5개 | 읽을 때 형식 검증, 이상하면 `[]` |
| `merge-tiles:state` | 진행 중 게임 상태 JSON | (선택 기능 2) 매 이동 후 저장, 오버/새 게임 시 갱신 |
| `theme` | `'light'` \| `'dark'` | **블로그와 공유하는 키** (읽기 + 토글 시 쓰기) |

- 모든 `getItem`/`setItem`/`JSON.parse`를 `try/catch`로 감싸고 실패 시 기본값 사용 → 사생활 보호 모드에서도 게임은 정상 동작(이번 방문 동안만 유지).
- 블로그와 같은 오리진이므로 키 충돌 방지를 위해 `merge-tiles:` 접두사 사용.

### 5.7 렌더링과 애니메이션 (`render.js`)
- 배경 격자(빈 셀 16개)는 정적 DOM, 타일은 그 위의 **절대 배치 레이어**에 `id`별 요소로 유지(`Map<id, HTMLElement>`).
- 위치는 CSS 변수로 지정: `style="--row: 2; --col: 1"` → `transform: translate(calc(var(--col) * (var(--cell) + var(--gap))), ...)`. `transition: transform 120ms ease-out`.
- 한 턴의 렌더 순서
  1. `moves`: 기존 타일 요소의 `--row/--col` 갱신 → 슬라이드
  2. 120ms 후: 흡수된 두 타일 요소 제거, 합쳐진 새 타일 생성(`.is-merged` → 140ms scale 1→1.12→1 팝)
  3. 새 타일 생성(`.is-new` → 160ms scale 0→1 + fade)
- **연타 처리**: 애니메이션 중 다음 입력이 오면 진행 중인 애니메이션을 즉시 최종 상태로 확정(`finishPending()`)한 뒤 새 이동을 처리 → 입력 손실·좌표 꼬임 없음. 입력 큐는 최대 1개.
- `prefers-reduced-motion: reduce`: 슬라이드/팝을 끄고(duration 0) 즉시 배치.
- 타일 색은 클래스 `tile--v2` … `tile--v1024`, 2048 이상은 `tile--super` 하나로 통합. 4자리 이상은 `tile--small-text`.

### 5.8 입력 (`input.js`)
- **키보드**: `keydown`을 `document`에 등록. `ArrowLeft/Right/Up/Down`, `KeyA/D/W/S`(`event.code` 사용 → 한/영 IME 상태와 무관). 수정 키(Ctrl/Alt/Meta) 동반 시 무시(단 `Ctrl+Z`는 되돌리기). 입력 포커스가 `<dialog>`나 텍스트 입력 안이면 무시. 방향 처리 시 `preventDefault()`.
- **스와이프**: 보드 요소에 `pointerdown` → `pointerup`/`pointercancel`. `setPointerCapture` 사용. 이동 거리 30px 이상 & 주축 성분이 부축의 1.5배 이상일 때만 방향 인정. 보드에 `touch-action: none`, `user-select: none`, `overscroll-behavior: contain`.
- 길게 누름 메뉴·더블탭 확대 방지: 보드에 `-webkit-touch-callout: none`.

## 6. 테마 처리

### 6.1 단독 페이지 (`apps/merge-tiles/index.html`)
- `<head>` 안에 블로그와 **동일한 로직의 인라인 스크립트**를 CSS 링크보다 먼저 둠 → FOUC 방지.
  - 우선순위: ① URL 파라미터 `?theme=light|dark` (임베드용) → ② `localStorage.theme` (블로그와 공유) → ③ `prefers-color-scheme`
  - 결과를 `<html data-theme="...">`에 적용, `meta[name="theme-color"]` 갱신.
- `style.css`의 `:root` / `:root[data-theme="dark"]`에 블로그 변수 값을 복제하고, 게임 전용 변수(`--tile-2-bg`, `--tile-2-fg`, …, `--board-bg`, `--cell-bg`, `--overlay-bg`)를 두 테마 각각 정의. 컴포넌트에는 하드코딩 색상 없음.
- `<meta name="color-scheme" content="light dark">`.
- **테마 토글 버튼**(헤더): 블로그와 같은 `theme` 키에 저장 → 블로그로 돌아가도 같은 테마 유지. `aria-label`을 "다크 모드로 전환"/"라이트 모드로 전환"으로 갱신.

### 6.2 변화 추적 (`theme.js`)
- `window.addEventListener('storage', e => e.key === 'theme' ...)`: 다른 탭이나 **같은 오리진의 부모 페이지(블로그)에서 토글**하면 iframe 안에서도 자동 반영(같은 오리진 문서 간에는 `storage` 이벤트가 전달됨).
- `matchMedia('(prefers-color-scheme: dark)')` 변경: 저장된 값이 없을 때만 따라감.
- **postMessage (보조 수단)**: 부모가 `{ type: 'merge-tiles:theme', theme: 'dark' }`를 보내면 적용. `event.origin === location.origin`인 메시지만 수락하고, `theme` 값은 `'light'|'dark'` 화이트리스트 검증.

### 6.3 iframe 임베드 시
- 임베드 URL: `apps/merge-tiles/index.html?embed=1` (필요 시 `&theme=dark`).
- `embed=1`이면 `<html data-embed>` → 헤더(블로그 링크·토글)와 기록 목록 숨김, 여백 축소, 배경 투명/`--color-surface`로 카드와 어울리게.
- 테마는 같은 오리진이라 `localStorage.theme` + `storage` 이벤트만으로 부모와 동기화됨. URL 파라미터·postMessage는 다른 오리진에서 호스팅될 경우를 대비한 폴백.
- iframe 안 키보드 조작은 iframe이 포커스를 가져야 하므로 "클릭해서 시작" 안내를 보드 위에 표시(첫 포인터 입력/포커스 시 사라짐).

### 6.4 대비
- 모든 타일의 숫자/배경 조합을 두 테마에서 **WCAG AA 4.5:1 이상**으로 맞춤(큰 굵은 숫자는 3:1 기준이 허용되지만 여유 있게 4.5:1 목표). Build 단계에서 값 확정 시 대비 표를 주석으로 남김.

## 7. 접근성

- **시맨틱 구조**: `header`, `main`, `section`(점수판/기록), `footer`, 기록 목록은 `<ol>`, 날짜는 `<time datetime>`.
- **보드**: `role="group"` + `aria-label="게임판. 방향키 또는 WASD로 타일을 밉니다."`, `tabindex="0"`(포커스 가능, iframe·키보드 사용자용). 개별 타일은 `aria-hidden="true"`로 두고 상태는 아래 알림으로 전달(16칸을 매 턴 읽게 하면 소음이 크기 때문).
  - 대신 보이지 않는 "판 읽기" 버튼(`B` 키도 가능)을 제공해 요청 시 현재 판을 행 단위로 읽어 줌: "1행: 2, 빈칸, 8, 빈칸 …" (선택이지만 비용이 작아 포함 권장).
- **aria-live**
  - `role="status"` (`aria-live="polite"`) 영역 1개: "점수 1,284 (+32)". 연타 시 마지막 값만 읽도록 300ms 디바운스.
  - 메달 획득: 같은 영역에 "골드 메달 달성".
  - 게임 오버: `aria-live="assertive"` 영역에 "게임 오버. 최종 점수 5,920, 최고 타일 512." 그리고 오버레이의 "다시 하기" 버튼으로 포커스 이동.
  - 이동 불가 입력: 알리지 않음.
- **포커스**
  - 모든 버튼에 `:focus-visible` 링(accent 색, 2px outline + offset).
  - 새 게임 확인 `<dialog>`는 `showModal()` 사용 → 포커스 트랩·`Esc` 닫기 기본 제공, 닫히면 원래 버튼으로 포커스 복귀.
  - 오버레이를 닫고 되돌리기/새 게임 후에는 보드로 포커스 복귀.
- **크기**: 모든 버튼·링크 터치 대상 최소 44×44px. 점수 숫자는 `tabular-nums`로 자릿수 변화 시 흔들림 없음.
- 되돌리기 버튼은 사용 불가 시 `disabled` + 라벨 "되돌리기 (0회 남음)".
- 색만으로 정보 전달하지 않음: 메달은 색 + 글자(동/은/금/백금) + `aria-label`, 미획득은 "미획득" 텍스트(시각적 숨김) 포함.
- `prefers-reduced-motion` 존중.

## 8. Embed 계획 (제안 — 별도 단계에서 진행)

> 이 단계에서는 블로그 파일을 수정하지 않습니다. 아래는 Embed 단계 담당자를 위한 제안입니다.

### 구조적 사실
- 블로그 `index.html`은 SPA 셸이고, 글 목록 화면은 `js/views.js`의 `renderHome()`이 `hero → 검색 → "모든 글" 목록` 순서로 HTML을 만듭니다. 따라서 "메인에 카드 추가"는 실제로는 **`js/views.js`(+ `css/style.css`)** 수정이 필요합니다. `index.html` 정적 마크업에 넣으면 모든 라우트(글 상세 등)에 카드가 보이게 되므로 권장하지 않습니다.

### 제안안 (권장: A + 선택적 B)
- **A. 정적 미리보기 카드 (기본)**
  - `renderHome()`에서 hero 다음, "모든 글" 앞에 `<section aria-labelledby="apps-title">` "미니 웹앱" 섹션 추가.
  - 카드 내용: 제목 "머지 타일", 설명 "방향키나 스와이프로 숫자 타일을 밀어 합치는 퍼즐. 메달과 최고 기록에 도전해 보세요.", 미리보기 `apps/merge-tiles/preview.svg`(`<img alt="머지 타일 게임 화면 미리보기" width height loading="lazy">`), 링크 `apps/merge-tiles/index.html`(카드 전체 클릭 영역, 44px 이상).
  - 카드 스타일은 기존 글 카드(`renderPostCard`) 디자인을 재사용해 톤 통일.
  - 확장성: 앱이 늘어날 것을 고려해 `apps/index.json` 매니페스트(`[{ slug, title, description, preview, href }]`)를 두고 `app.js`가 글 매니페스트처럼 fetch하는 방식 제안.
- **B. iframe 라이브 미리보기 (선택)**
  - 카드 안에 "여기서 바로 해보기" 버튼 → 클릭 시에만 `<iframe src="apps/merge-tiles/index.html?embed=1" title="머지 타일 게임" loading="lazy">`을 삽입(클릭 전 로드 안 함).
  - 이유: 메인 페이지에서 iframe이 처음부터 있으면 ① 로딩 비용, ② 블로그 스크롤 중 스와이프/방향키를 게임이 가로채는 문제가 생김. 클릭으로 명시적으로 활성화하면 이 문제를 피할 수 있음.
  - iframe 크기: `width: 100%; aspect-ratio: 3 / 4; max-width: 28rem`, 테두리 없음, `--radius` 적용.
- 테마 동기화는 6.3대로 같은 오리진 `localStorage` + `storage` 이벤트로 자동 처리되므로 부모 쪽 추가 코드 불필요(원하면 `theme.js`의 `applyTheme`에서 iframe에 postMessage를 보내는 한 줄 추가 가능).
