# 스택 드롭 — Review 보고서

> 단계: Review · 작성일: 2026-11-28 · 검토 대상: `apps/stack-drop/` (spec.md 기준)
> Build와 독립적으로 검증했다. Node 테스트는 Build 테스트를 재사용하지 않고 새로 작성했고(저장소 밖 임시 폴더, 종료 후 삭제),
> 브라우저 검증은 내장 브라우저에서 `requestAnimationFrame`을 가로채 16.67ms 가짜 타임스탬프로 직접 진행시키는 스테퍼로 했다.

## 요약 — **조건부 통과**

- 핵심 요구 2개(회전·벽 차기, ↓ 누르는 동안만 빠른 낙하)는 실제 앱 코드 경로에서 수치로 확인했고 모두 **통과**.
- 게임 로직 38개 + 저장소 검증 테스트 전부 통과. 콘솔 오류 0건, 외부 네트워크 요청 0건.
- 기능 버그는 없었다. 시각·문구 문제 3건을 고쳤다(격자선이 너무 진함, 데스크톱 점수판 간격 벌어짐, 줄 삭제 낭독 문구).
- "조건부"인 이유: 실기기 터치, 스크린리더 실제 낭독, `prefers-reduced-motion` 실제 화면, 120Hz 화면, DPR 3은 이 환경에서 확인하지 못했다(아래 "남은 한계").

| 후보 순서표 | Node | J/L/S/T/Z `(0,0)(−1,0)(+1,0)(0,−1)(−1,−1)(+1,−1)`, I `…(−2,0)(+2,0)(0,−1)`, 반시계는 좌우 반대 — 기획서 6.4와 일치 |
| 오른쪽 벽 −1 차기 | Node | rot3 T가 오른쪽 벽에 붙은 상태에서 시계 회전 → x−1 |

| 완전히 막힘 | Node | 회전·좌표 변화 없음 |

## 핵심 요구 2 — ↓를 누르는 동안만 빠르게, 떼면 원래 속도: **통과**

레벨 1(중력 1000ms, 소프트 드롭 50ms) 실측. 1프레임 = 16.67ms.

| 상황 | 입력 | 측정값 |
|---|---|---|
| 기본 중력 | 없음 | 1000 / 2000 / 3000ms에 1칸씩 (정확히 1000ms 간격) |
| ↓ 키 누르고 있기 | `ArrowDown` keydown 유지 | 누른 즉시 1칸 + 이후 50ms마다 1칸 → 200ms에 5칸, 점수 +5(칸당 1점) |
| ↓ 키 뗌 | keyup | 뗀 뒤 1000ms·2000ms에 1칸씩 — 즉시 원래 속도 복귀, 점수 증가 멈춤 |
| ↓ 누른 채 바닥 도달 | 계속 누름 | 333ms에 접지 → 약 500ms 뒤 고정(817ms). 소프트 드롭이 고정 지연을 줄이지 않음 |
| ↓ 누른 채 다음 조각 | 계속 누름 | 새 조각도 바로 50ms 간격으로 낙하 |
| 모바일 ↓ 버튼 누르고 있기 | `pointerdown`(touch, id 11) 유지 | 150ms에 4칸(즉시 1 + 50ms마다), `is-pressed` 표시 |
| ↓ 버튼 `pointercancel` | | 즉시 해제, 이후 600ms 동안 낙하 0칸(원래 1000ms 간격) |
| ↓ 버튼에서 손가락이 밖으로 미끄러짐 | `pointermove` 버튼 위 40px | 해제, 500ms 동안 낙하 0칸 |
| 레벨 2 중력 | 10줄 삭제 후 | 817ms 간격(820ms, 프레임 양자화 오차) |
| 소프트 드롭 간격 공식 | Node | 레벨 1: 50, 3: 33.6, 5·10·17: 25ms (`min(중력, max(중력/20, 25))`) |

입력 상태가 꼬이는 경우도 확인했다.

| 상황 | 결과 |
|---|---|
| ↓ 누른 채 P로 일시정지 → 일시정지 중 keyup → P로 재개 | 재개 후 400ms 낙하 0칸 (소프트 드롭 남지 않음) |
| ↓ 누른 채 창 `blur`(keyup 없음) → 자동 일시정지 → 계속하기 | 재개 후 400ms 낙하 0칸 |
| 탭 숨김(`visibilitychange`) | 자동 일시정지, 다시 보여도 자동 재개 안 함 |
| 일시정지 중 시간이 흐른 뒤 재개 | 첫 프레임 dt=0, 순간 낙하 없음 |
| ↓ 누른 상태의 멀티 터치 ← | 소프트 드롭 유지하며 ← DAS 반복(벽까지 3칸) |

## 발견한 문제와 조치

1. **격자선이 너무 진함** (Build 확인 요청 항목) — `style.css`
   - 문제: 격자선이 판 배경 대비 3.4:1이라 판 전체가 촘촘한 그물처럼 보이고 블록·그림자와 경쟁했다. 기획서 4장의 "격자선 매우 옅게"와 맞지 않는다.
   - 판단: 기획서 안에서 4장("매우 옅게")과 10장 체크리스트("격자 3:1 이상")가 충돌한다. 격자는 칸 위치를 돕는 장식 요소라 WCAG 1.4.11(비텍스트 대비) 대상이 아니므로 4장을 우선했다. 블록 7톤과 그림자 윤곽은 3:1 이상을 그대로 유지한다.
   - 조치: `--grid-line` 라이트 `#6a8a87` → `#b4cbc8`(1.55:1), 다크 `#52716f` → `#2a4143`(1.64:1). 라이트·다크·320px 화면에서 칸이 여전히 구분되는 것을 확인했다. CSS 주석에 이유를 남겼다.
2. **데스크톱 점수판 줄 간격이 지나치게 벌어짐** — `style.css`
   - 문제: 데스크톱 그리드에서 HUD가 두 행(기록·키 안내 높이)에 걸쳐 늘어나, 점수/최고/레벨/줄 각 행이 71px로 벌어졌다.
   - 조치: 데스크톱 `.hud`에 `align-self: start` 추가 → 각 행 35px.
3. **줄 삭제 낭독 문구가 다음 알림과 붙음** — `js/main.js`
   - 문제: `"1줄 삭제, +150점. 연속 2번째"`처럼 마침표 뒤에 연속 정보가 붙어, 디바운스로 합쳐지면 "…연속 2번째 1줄 삭제…"로 읽혔다.
   - 조치: `"1줄 삭제, 연속 2번째, +150점."` 형식으로 변경.

모바일 판 높이 계산(Build 확인 요청 항목)은 문제없었다. `--chrome-h`(헤더 + HUD + 버튼 2줄 + 간격 + 여백)를 뺀 높이로 셀을 정하며, 375×812·375×667·320×568에서 판·미리보기·버튼이 모두 첫 화면에 들어오고 셀 하한 14px을 지킨다.

## 남은 한계

- **실기기 미확인**: 실제 터치에서의 스크롤·더블탭 확대·당겨서 새로고침 차단, 길게 누름 메뉴, 제스처(탭 회전·드래그·튕기기). 합성 PointerEvent로는 브라우저 기본 동작을 재현할 수 없다.
- **스크린리더 실제 낭독**, `prefers-reduced-motion` 화면, 120Hz 이상 화면, DPR 3, `storage` 이벤트(다른 탭), OS 테마 변경 반영, GitHub Pages 하위 경로는 코드 리뷰로만 확인했다.
- 브라우저 창이 숨겨진 상태라 실제 rAF와 CSS 애니메이션이 거의 돌지 않았다. 게임 진행은 가짜 타임스탬프 스테퍼로 앱 코드 경로를 그대로 실행해 검증했지만, 오버레이 페이드인 같은 CSS 애니메이션은 중간 프레임에서 캡처될 수 있었다(최종 상태 불투명도 1 확인).
- 사소한 관찰(수정 안 함): 일시정지 중에 ↓를 누르고 그대로 재개하면 다시 눌러야 소프트 드롭이 된다(재개 시 입력을 모두 해제하는 안전한 쪽 동작). 위로 차기 등으로 칸 일부가 판 위(by < 0)에 있는 채 고정되면 게임 오버로 처리한다(기획서의 "4칸 모두 버퍼" 조건보다 약간 넓지만 보드 밖 칸을 기록할 수 없으므로 합리적).
