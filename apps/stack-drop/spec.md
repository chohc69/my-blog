## 1. 개요와 게임 규칙

### 개요
**스택 드롭**은 위에서 떨어지는 4칸짜리 블록 조각을 좌우로 옮기고 돌려 쌓다가, 가로 한 줄을 빈틈없이 채우면 그 줄이 사라지는 낙하 블록 퍼즐입니다.
줄을 지울수록 레벨이 오르고 조각이 빨리 떨어집니다. 쌓인 블록이 맨 위에 닿을 때까지 버티며 점수를 겨루는 **끝없는 기록 도전형** 게임입니다.
`apps/stack-drop/` 안에 순수 HTML/CSS/JS(ES Modules)로 자체 완결되며, 블로그 테마와 다크 모드를 따릅니다.

> 독자성 원칙
> - 이름은 "스택 드롭 (Stack Drop)"만 씁니다. UI·주석·메타 태그 어디에도 "테트리스/Tetris"를 쓰지 않습니다.
> - 유명 게임의 조각별 고정 무지개 배색(하늘색 막대, 노란 정사각형, 보라 T 등), 로고, 음악, 화면 구성을 따르지 않습니다.
> - 회전 보정은 공개된 특정 게임의 상세 표를 옮기지 않고, 아래 5.4의 **자체 단순 규칙**을 씁니다.
> - 조각 이름(I, O, T, S, Z, J, L)은 4칸 조각(테트로미노)의 수학적 일반 명칭이라 **코드 내부 식별자로만** 쓰고 화면에는 표시하지 않습니다.

### 1.1 판
- 보이는 판: **가로 10칸 × 세로 20칸**. 그 위에 보이지 않는 **버퍼 2줄**(전체 22줄, 0·1행 숨김).
- 이유: 10칸 폭은 4칸 조각 7종이 여유 있게 놓이는 장르 표준 비율이고, 버퍼 2줄이 있어야 조각이 판 밖에서 생성되어 자연스럽게 들어옵니다.

### 1.2 조각 — 4칸 조각 7종 (결정)
| 내부 id | 모양(생성 방향) | 회전 상자 |
|---|---|---|
| I | `████` 일자 | 4×4 |
| O | `██/██` 정사각 | 2×2 (회전 없음) |
| T | `.█./███` | 3×3 |
| S | `.██/██.` | 3×3 |
| Z | `██./.██` | 3×3 |
| J | `█../███` | 3×3 |
| L | `..█/███` | 3×3 |

**이유**: 4칸으로 만들 수 있는 모든 모양(7종)을 다 쓰면 이 장르의 "읽히는" 손맛과 난이도가 가장 잘 균형 잡힙니다. 5칸 조각을 섞으면 10칸 폭에서 지나치게 어려워지고, 7종보다 줄이면 단조로워집니다.

### 1.3 랜덤 생성 — 7개 주머니 방식 (결정)
- 7종을 한 주머니에 넣고 섞어(Fisher–Yates) 순서대로 꺼내고, 비면 다시 채웁니다.
- **이유**: 순수 무작위는 일자 조각이 수십 개 동안 안 나오는 "가뭄"이 생겨 운이 실력을 압도합니다. 주머니 방식은 같은 조각 간격이 최대 12개로 보장되어 공정하고, 다음 조각 미리보기 전략이 의미를 갖습니다.
- 난수 함수는 주입 가능(`rng`)하게 해 테스트에서 고정 순서를 넣을 수 있게 합니다.

### 1.4 낙하
- **자동 낙하(중력)**: 레벨별 간격마다 1칸 내려갑니다.
- **소프트 드롭(↓ 누르고 있기)**: 누르고 있는 동안 낙하 간격이 `min(중력 간격, max(중력 간격 / 20, 25ms))`로 짧아집니다. 떼면 즉시 원래 속도로 돌아옵니다. 칸당 **+1점**.
- **하드 드롭(Space)**: 바닥(그림자 위치)까지 즉시 떨어지고 **즉시 고정**됩니다. 떨어진 칸당 **+2점**.
- **그림자(고스트)**: 지금 하드 드롭하면 놓일 위치를 옅은 윤곽으로 표시합니다.

### 1.5 고정(lock)
- 조각이 더 내려갈 수 없는 상태(접지)가 되면 **고정 지연 500ms** 후 판에 고정됩니다.
- 접지 상태에서 이동·회전에 **성공**하면 지연이 다시 500ms로 초기화됩니다. 단 **조각당 최대 15회**까지만 초기화되고, 조각이 지금까지보다 더 낮은 행에 도달하면 횟수도 0으로 돌아갑니다.
- 이유: 지연이 없으면 빠른 레벨에서 바닥 근처 미세 조정이 불가능하고, 무한 초기화를 허용하면 조각을 영원히 붙잡아 둘 수 있습니다. 15회 제한이 두 문제를 함께 막습니다.
- 소프트 드롭 중이라도 고정 지연은 줄이지 않습니다(실수로 고정되는 것 방지). 즉시 고정은 하드 드롭으로만.

### 1.6 줄 삭제
- 고정 직후 가득 찬 행을 모두 찾아 지우고, 위의 행들을 그만큼 내립니다(중력 연쇄 없음, 단순 행 이동).
- 지우는 동안 **250ms 삭제 연출**(행이 밝게 번쩍이며 가로로 사라짐) 후 다음 조각이 나옵니다. `prefers-reduced-motion`이면 연출 없이 120ms 정지만.
- 줄 삭제가 없으면 다음 조각이 지연 없이 바로 나옵니다.

### 1.7 레벨과 속도
- 시작 레벨 1. **누적 10줄마다 레벨 +1** (`level = startLevel + floor(lines / 10)`).
- 중력 간격: `gravityMs(level) = max(50, round(1000 × 0.82^(level − 1)))`

| 레벨 | 1 | 2 | 3 | 5 | 8 | 10 | 12 | 15 | 17+ |
|---|---|---|---|---|---|---|---|---|---|
| 간격(ms) | 1000 | 820 | 672 | 452 | 249 | 168 | 113 | 62 | 50 |

- 이유: 지수 감소는 초반엔 체감 변화가 크고 후반엔 완만해 학습 곡선이 자연스럽습니다. 50ms 하한은 60Hz 화면에서 3프레임마다 1칸으로, 사람이 아직 반응 가능한 한계로 잡았습니다.

### 1.8 점수 공식 (자체 규칙)
| 항목 | 점수 |
|---|---|
| 1줄 삭제 | 100 × 레벨 |
| 2줄 동시 | 300 × 레벨 |
| 3줄 동시 | 600 × 레벨 |
| 4줄 동시 | 1000 × 레벨 |
| 연속 삭제 보너스 | 줄을 지운 고정이 연속될 때 `50 × (연속 횟수 − 1) × 레벨` (2번째 연속부터) |
| 소프트 드롭 | 1 / 칸 |
| 하드 드롭 | 2 / 칸 |

- 줄 점수는 `100 × n(n+1)/2`(삼각수) 형태입니다. 한 번에 많이 지울수록 이득이지만, 1줄씩 꾸준히 지우는 플레이도 손해가 지나치지 않게 했습니다.
- 연속 보너스는 "한 줄씩이라도 끊기지 않고 지우는" 다른 전략을 보상해 플레이 스타일을 다양하게 합니다.
- 레벨 계산과 점수 계산 순서: 삭제 점수는 **삭제 전 레벨**로 계산한 뒤, 줄 수를 더하고 레벨을 갱신합니다.

### 1.9 게임 오버
- **생성 막힘**: 새 조각이 생성 위치에서 이미 블록과 겹치면 게임 오버.
- **위로 넘침**: 고정된 조각의 4칸이 **모두 버퍼(0·1행)** 안에 있으면 게임 오버.
- 게임 오버 시 입력 중지, 오버레이(최종 점수·줄·레벨·"다시 하기"), 기록 저장.

## 2. 기능 목록

### 필수
- [ ] 10×20 판(+버퍼 2줄), 4칸 조각 7종, 7개 주머니 생성
- [ ] ←/→ 이동, ↑·X 시계 방향 회전, Z 반시계 회전, 단순 벽 차기
- [ ] ↓ 누르고 있는 동안 소프트 드롭, Space 하드 드롭, 그림자 표시
- [ ] 자체 키 반복(DAS/ARR), 브라우저 키 반복(`event.repeat`) 무시
- [ ] 고정 지연 500ms + 초기화 15회 제한
- [ ] 줄 삭제(연출 포함), 점수·레벨·삭제 줄 수 표시, 레벨별 낙하 속도
- [ ] 다음 조각 미리보기 **3개**(첫 번째는 크게)
- [ ] 일시정지/재개(P, Esc, 화면 버튼), 탭 숨김·창 포커스 잃음 시 자동 일시정지
- [ ] 시작 화면(“시작” 버튼 / Enter) — 사용자가 시작하기 전에는 키를 가로채지 않음
- [ ] 점수판: 현재 점수, 최고 점수, 상위 기록 Top 5 (`localStorage`, 모든 접근 `try/catch`)
- [ ] 게임 오버 판정, 오버레이, 다시 하기
- [ ] 모바일 화면 버튼: ← → (누르고 있으면 반복), ↓ 누르고 있기, 시계/반시계 회전, 하드 드롭, 일시정지
- [ ] 라이트/다크 모드(블로그 `theme` 키 공유, 시스템 설정 폴백), `?embed=1`, `?theme=`
- [ ] `requestAnimationFrame` 기반 게임 루프, 375px 폭 가로 스크롤 없음

### 선택 (우선순위 순, 1·2는 이번 Build에 포함 권장)
1. **보관(Hold)**: C / Shift 키, 모바일 버튼. 조각당 1회만 교체 가능. 이유: 비용이 작고 전략성이 크게 늘어남.
2. **시작 레벨 선택**(1–10): 시작 화면에서 `<select>`. 기록에 시작 레벨도 저장.
3. **터치 제스처**(게임판 위): 탭 = 시계 회전, 좌우 드래그 = 칸 단위 이동(셀 폭만큼 끌 때마다 1칸), 아래로 끌기 = 소프트 드롭, 빠른 아래 튕기기(속도 > 1.2px/ms) = 하드 드롭. 버튼과 동시에 사용 가능.
4. **키 반복 설정**: DAS/ARR 슬라이더(설정 저장).
5. 다시 시작 단축키 R(확인 대화상자).

### 범위 밖
- 진행 중 게임 이어하기(실시간 게임이라 새로고침 뒤 복원은 공정성·혼란 문제가 커서 제외), 사운드·음악, 온라인 랭킹, 대전, T자 회전 특수 판정 같은 고급 기술 점수, 외부 라이브러리.

## 3. 조작표와 키 반복 타이밍

### 3.1 키보드 (`event.code` 사용 → 한/영 IME 상태와 무관)
| 동작 | 키 | 반복 |
|---|---|---|
| 왼쪽 / 오른쪽 이동 | `ArrowLeft` / `ArrowRight` (보조: `KeyA` / `KeyD`) | DAS/ARR |
| 소프트 드롭 | `ArrowDown` (보조: `KeyS`) 누르고 있기 | 누르는 동안 빠른 중력 |
| 하드 드롭 | `Space` | 반복 없음(누를 때 1회) |
| 시계 방향 회전 | `ArrowUp`, `KeyX` (보조: `KeyW`) | 반복 없음 |
| 반시계 방향 회전 | `KeyZ` | 반복 없음 |
| 보관 (선택) | `KeyC`, `ShiftLeft/Right` | 반복 없음 |
| 일시정지 / 재개 | `KeyP`, `Escape` | — |
| 시작 / 다시 하기 | `Enter` (시작 화면·게임 오버 오버레이에서) | — |

- 게임 진행 중(또는 일시정지 중) 위 키에 대해서만 `preventDefault()` → 방향키·Space로 페이지가 스크롤되지 않음. 시작 전·대화상자 열림·텍스트 입력 포커스 중에는 가로채지 않음.
- Ctrl/Alt/Meta 동반 입력은 무시(브라우저 단축키 보존).
- `window` `blur` 시 눌린 키 상태를 모두 해제(키가 눌린 채로 남는 버그 방지) + 자동 일시정지.

### 3.2 키 반복 타이밍 (결정)
| 값 | 기본 | 설명 |
|---|---|---|
| DAS (첫 반복까지 지연) | **160ms** | 누르는 즉시 1칸 이동 → 160ms 동안 유지되면 반복 시작 |
| ARR (반복 간격) | **40ms** | 반복 중 40ms마다 1칸 (초당 25칸) |
| 소프트 드롭 간격 | `min(중력, max(중력/20, 25ms))` | 레벨 1에서 50ms(초당 20칸), 고레벨 하한 25ms |

- **이유**: 160ms는 "한 칸만 옮기려고 짧게 누른" 입력과 "끝까지 밀려는" 입력을 구분하기에 충분하고, 40ms는 판 끝까지(최대 9칸) 약 0.5초로 빠르면서도 눈으로 따라갈 수 있습니다. 브라우저 자체 키 반복은 OS마다 지연이 달라(보통 250–500ms) 쓰지 않습니다.
- **좌우 동시 입력**: 나중에 누른 방향이 우선. 그 키를 떼면 아직 눌린 반대 방향이 DAS를 처음부터 다시 시작.
- DAS 타이머는 조각이 바뀌어도 유지(누른 채로 다음 조각도 바로 반복 이동 가능). 벽에 막혀도 타이머는 계속 진행.
- 반복 타이머는 게임 루프의 `dt`로 진행(별도 `setInterval` 없음) → 일시정지 시 함께 멈춤.

### 3.3 모바일 화면 버튼 (Pointer Events)
```
 [ ⟲ ]                         [ ⟳ ]      ← 반시계 / 시계 회전 (탭 1회)
 [ ← ]   [ ↓ 누르기 ]   [ → ]   [ ⤓ ]      ← 이동(DAS/ARR), 소프트 드롭(누르는 동안), 하드 드롭
```
- 각 버튼 최소 **56×56px**(권장, 44px 이상 필수), 버튼 간 간격 8px 이상.
- `pointerdown`에서 동작 시작 + `setPointerCapture`, `pointerup`/`pointercancel`/`lostpointercapture`에서 해제. 키보드와 **같은 입력 계층**(가상 키 `left/right/down/...`)으로 들어가 DAS/ARR가 동일하게 적용.
- 멀티 터치 허용: ↓를 누른 채 ←/→ 동시 사용 가능(포인터 id별 추적).
- `contextmenu` 차단, `touch-action: none`, `user-select: none`, `-webkit-touch-callout: none`, `-webkit-tap-highlight-color: transparent`.
- 버튼은 화면 하단에 엄지가 닿는 위치. 일시정지 버튼은 상단 HUD 오른쪽(오조작 방지 위해 조작 버튼과 떨어뜨림).

## 4. 화면 구성

### 공통 요소
- **헤더**: "← 블로그" 링크(`../../index.html`), 앱 이름 "스택 드롭", 테마 토글
- **HUD**: 점수, 최고, 레벨, 줄 / 일시정지 버튼
- **판**: `<canvas>` 10×20, 옅은 격자선, 그림자 조각
- **다음 조각**: 1개 크게 + 2개 작게, (선택) 보관 칸
- **오버레이**(판 위): 시작 / 일시정지 / 게임 오버
- **기록**: Top 5 (`<ol>`), 비어 있으면 "아직 기록이 없어요"
- **조작 안내**: 데스크톱은 키 안내 표, 모바일은 버튼 자체가 안내

### 모바일 (기본, < 768px) — 한 화면에 판과 버튼이 모두 보이게
```
┌───────────────────────────────┐  좌우 여백 16px
│ ← 블로그    스택 드롭     [◐] │  헤더 48px
├───────────────────────────────┤
│ 점수 12,340  최고 40,120  [❚❚]│  HUD 1줄
│ 레벨 4   줄 31                │
```

## 6. 핵심 로직 설계

### 6.1 상태 구조 (`game.js`)
```js
{
  phase: 'ready',          // 'ready' | 'playing' | 'paused' | 'clearing' | 'over'
  board: Uint8Array(220),  // 10 × 22, row-major. 0 = 빈칸, 1~7 = 조각 종류(색 인덱스 + 1)
  piece: { type: 'T', rot: 0, x: 3, y: 0 },  // 회전 상자 왼쪽 위 기준 좌표
  queue: ['S', 'I', 'L'],  // 미리보기 3개 (randomizer에서 보충)
  hold: null,              // (선택) 보관 조각 type
  holdUsed: false,         // 이번 조각에서 보관 사용 여부
  score: 0,
  lines: 0,
  level: 1,
  startLevel: 1,
  combo: -1,               // 연속 삭제 카운터 (-1 = 끊김)
  timers: {
    gravity: 0,            // 다음 낙하까지 누적 ms
    lock: 0,               // 접지 후 누적 ms
    lockResets: 0,
    lowestY: 0,            // 이 조각이 도달한 가장 낮은 y (초기화 횟수 리셋용)
    clear: 0,              // 삭제 연출 누적 ms
  },
  clearingRows: [],        // 삭제 연출 중인 행 번호
}
```
- 직렬화 가능한 평범한 객체(Uint8Array 제외 시 JSON 가능). 게임 진행 중 상태는 저장하지 않으므로 직렬화는 테스트용.
- `game.js`는 상태를 **제자리에서 갱신**(실시간 게임이라 매 프레임 복사 비용을 피함). 대신 모든 변경은 `game.js` 함수로만 수행.

### 6.2 조각 정의 (`pieces.js`)
- 각 조각은 회전 상자 크기 `n`과 생성 방향 셀 목록 `[[x, y], ...]`로 정의.
- 회전 상태 0~3을 로드 시 한 번 계산: 시계 방향 회전 `(x, y) → (n − 1 − y, x)`. O는 상태 1개.
- 결과: `SHAPES[type][rot] = [[x, y] × 4]` — 충돌 판정은 이 표만 참조.

### 6.3 충돌 판정
```
collides(board, type, rot, x, y):
  for [cx, cy] of SHAPES[type][rot]:
    bx = x + cx; by = y + cy
    if bx < 0 or bx >= 10 or by >= 22: return true   // 좌우 벽, 바닥
    if by >= 0 and board[by * 10 + bx] != 0: return true
  return false
```
- 위쪽(by < 0)은 벽으로 보지 않음(버퍼 위로 회전해도 허용). 모든 이동·회전·낙하·그림자 계산이 이 함수 하나를 씀.
- 그림자: `y`를 1씩 늘리며 충돌 직전까지 → `ghostY`. 조각이 움직일 때만 다시 계산.

### 6.4 회전과 벽 차기 — 자체 단순 규칙 (결정)
회전 시 새 회전 상태에서 아래 **오프셋 후보를 순서대로** 시험해, 처음으로 충돌하지 않는 위치를 채택합니다. 모두 실패하면 회전하지 않습니다.

| 조각 | 후보 순서 `(dx, dy)` (dy 음수 = 위로) |
|---|---|
| J, L, S, T, Z | `(0,0)`, `(−1,0)`, `(+1,0)`, `(0,−1)`, `(−1,−1)`, `(+1,−1)` |
| I | `(0,0)`, `(−1,0)`, `(+1,0)`, `(−2,0)`, `(+2,0)`, `(0,−1)` |
| O | 회전 없음 |

- 반시계 회전도 같은 표를 쓰되 좌우 순서를 뒤집음(`(+1,0)`을 `(−1,0)`보다 먼저) → 회전 방향 쪽으로 밀려나는 느낌이 자연스러움.
- **이유**
  - 벽 차기가 없으면 벽·바닥에 붙은 조각이 돌지 않아 답답합니다(사용자 요청 "회전 가능"의 체감 품질).
  - 특정 게임의 상태 쌍별 상세 표 대신 "제자리 → 좌우 1칸 → 위로 1칸" 규칙은 플레이어가 예측하기 쉽고 구현·테스트가 단순합니다.
  - 위로 1칸 차기(floor kick)는 바닥에서 회전을 돕지만, 고정 지연 초기화 15회 제한과 결합해 무한히 버티는 것은 막습니다.
  - 아래쪽 차기는 넣지 않습니다(조각이 블록 틈으로 "순간이동"하는 혼란 방지).
- 회전 성공 시 `lowestY` 비교 후 고정 지연 초기화 규칙(1.5) 적용.

### 6.5 랜덤 생성 (`randomizer.js`)
```
createBag(rng = Math.random):
  bag = []
  next(): if bag 비었음 → bag = shuffle(['I','O','T','S','Z','J','L'], rng)
          return bag.pop()
```
- 미리보기 큐는 항상 3개(+보관 교체용 여유) 유지. 새 게임마다 새 주머니.
- 생성 위치: `x = floor((10 − n) / 2)` (3×3·4×4 → 3, O → 4), `y = 0`(버퍼), 회전 0. 생성 직후 1칸 아래가 비어 있으면 즉시 1칸 내려 보이는 영역 첫 줄에 나타나게 함.

### 6.6 고정(lock) 지연
```
매 업데이트:
  grounded = collides(board, type, rot, x, y + 1)
  if grounded:
    timers.lock += dt
    if timers.lock >= 500 or (timers.lockResets >= 15 and 다시 접지됨): lockPiece()
  else:
    timers.lock = 0

이동/회전 성공 시:
  if y > timers.lowestY: lowestY = y; lockResets = 0
  if 접지 상태였다면 and lockResets < 15: timers.lock = 0; lockResets++
```
- 하드 드롭은 즉시 `lockPiece()`.
- `lockPiece()`: 보드에 기록 → 위로 넘침 검사 → 가득 찬 행 검사 → 있으면 `phase = 'clearing'`, 없으면 `combo = -1` 후 다음 조각 생성(막힘 검사).

### 6.7 줄 삭제
```
fullRows = 0..21 중 10칸이 모두 0이 아닌 행
if fullRows 있음:
  combo++
  score += LINE_SCORE[n] × level + (combo > 0 ? 50 × combo × level : 0)
  lines += n; level = startLevel + floor(lines / 10)
  phase = 'clearing'; clearingRows = fullRows; timers.clear = 0
clearing 단계: timers.clear += dt → 250ms(감소 모션 120ms) 도달 시
  행 제거(아래에서 위로 압축) → 다음 조각 생성 → phase = 'playing'
```
- clearing 중에는 입력에 의한 이동은 무시하되, DAS 타이머는 계속 진행(다음 조각 시작 시 바로 반복 이동 가능).

### 6.8 게임 루프 타이밍 (`loop.js`)
- `requestAnimationFrame(tick)`; `dt = min(now − last, 100)` → 탭 전환·디버거 정지 후 큰 dt로 조각이 순간 낙하하는 것 방지.
- 한 프레임 처리 순서: ① 입력 반복기 갱신(DAS/ARR로 이동 이벤트 생성) → ② 이동·회전·하드 드롭 적용 → ③ 중력 누적(`while (gravityAcc >= interval)` 1칸씩, 접지 시 중단) → ④ 고정 지연 → ⑤ 삭제 연출 진행 → ⑥ dirty면 렌더.
- 중력 간격은 소프트 드롭 여부에 따라 매 프레임 결정. 소프트 드롭으로 실제 내려간 칸만 +1점.
- 시간은 `performance.now()`(rAF 인자) 기준. 고주사율(120/144Hz) 화면에서도 ms 기반이라 속도 동일.
- **자동 일시정지**: `document.visibilitychange`(hidden) 및 `window.blur` 시 `phase = 'paused'`. 다시 보여도 **자동 재개하지 않고** "일시정지" 오버레이에서 사용자가 재개(P / 버튼). 재개 시 `last = now`로 초기화.
- 루프는 `ready`·`over`·`paused` 동안 rAF를 멈춰 배터리 절약(필요 시 연출용으로만 다시 시작).

### 6.9 게임 오버
- 6.5 생성 직후 `collides` → 생성 막힘.

## 7. 저장, 테마, 임베드

### 7.1 저장소 (`storage.js`)
| 키 | 값 | 비고 |
|---|---|---|
| `stack-drop:best` | 숫자 | 최고 점수. 게임 중 점수가 넘으면 HUD는 즉시 갱신, 저장은 고정마다(쓰기 빈도 낮음) |
| `stack-drop:records` | `[{ score, lines, level, date }]` 최대 5개 | 게임 오버 시 추가 → 점수 내림차순(동점이면 최근 우선) → 5개 유지. 들어가면 "새 기록" 강조 |
| `stack-drop:settings` | `{ startLevel, das, arr }` | 선택 기능 2·4 사용 시 |
| `theme` | `'light'` \| `'dark'` | **블로그와 공유하는 키** |

- 모든 `getItem`/`setItem`/`JSON.parse`를 `try/catch`로 감싸고, 읽은 값은 형식 검증(정수·범위·배열 길이·날짜 형식) 후 이상하면 기본값. 사생활 보호 모드에서도 정상 플레이.
- 같은 오리진의 다른 앱과 충돌하지 않도록 `stack-drop:` 접두사.
- 게임 중간에 나가면(새 게임 시작 포함) 그 판은 기록하지 않음 — 게임 오버된 판만 기록(실시간 게임이라 공정한 비교 기준).

### 7.2 테마
- 머지 타일과 **동일한 방식**:
  - `<head>` 인라인 스크립트가 CSS보다 먼저 실행: 우선순위 ① `?theme=light|dark` → ② `localStorage.theme`(try/catch) → ③ `prefers-color-scheme`. `<html data-theme>`, `meta[name="theme-color"]` 갱신.
  - `<meta name="color-scheme" content="light dark">`, `<meta name="viewport" content="width=device-width, initial-scale=1">`.
  - `style.css`의 `:root` / `:root[data-theme="dark"]`에 블로그 변수 복제 + 게임 변수(`--block-0`~`--block-6`, `--board-bg`, `--grid-line`, `--flash`, `--overlay-bg`, `--btn-pad-bg` …) 두 테마 각각 정의. 컴포넌트 하드코딩 색 없음.
  - 헤더 토글은 `theme` 키에 저장(블로그와 공유), `aria-label` "다크 모드로 전환"/"라이트 모드로 전환" 갱신.
  - `storage` 이벤트(다른 탭·같은 오리진 부모), `matchMedia` 변경(저장값 없을 때만), `postMessage`(`{ type: 'stack-drop:theme', theme }`, `event.origin === location.origin` + 값 화이트리스트) 반영.
- 추가: 테마 변경 시 `theme.js`가 `themechange` 콜백을 호출 → `render.js`가 CSS 변수 색 캐시를 다시 읽고 다시 그림(캔버스는 CSS 변화를 자동 반영하지 않으므로).

### 7.3 임베드 (`?embed=1`)
- `<html data-embed>` → 헤더·기록·키 안내 숨김, 여백 축소, 배경 `--color-surface`.
- 임베드에서는 **시작 버튼을 눌러야만** 게임이 시작되고 키를 가로챔(블로그 페이지 스크롤을 방해하지 않음). iframe이 포커스를 잃으면(`blur`) 자동 일시정지.
- 판 크기는 iframe 높이에 맞춰 같은 `ResizeObserver` 계산으로 축소.

## 8. 접근성

- **시맨틱**: `header`, `main`, `section`(점수판/다음 조각/기록), `footer`, 기록은 `<ol>` + `<time datetime>`. 점수판은 `<dl>`.
- **캔버스**: `role="img"` + `aria-label="게임판"` 한 줄만 두고, 실시간 상태는 아래 알림으로 전달. 매 프레임·매 이동을 읽지 않음(소음 방지).
- **aria-live**
  - `role="status"`(polite): 줄 삭제("2줄 삭제, +600점"), 레벨 업("레벨 5"), 일시정지/재개. 짧은 시간 연속 발생 시 400ms 디바운스로 합쳐 읽음.
  - `aria-live="assertive"`: 게임 오버("게임 오버. 점수 12,340, 31줄, 레벨 4.") + "다시 하기" 버튼으로 포커스 이동.
  - 다음 조각은 시각 미리보기 옆 시각적 숨김 텍스트로 모양 설명("다음: 일자 막대")을 두되, 자동 낭독하지 않음(요청 시 읽힘).
- **포커스**: 모든 버튼 `:focus-visible` 링(accent 2px + offset). 시작/일시정지/게임 오버 오버레이가 열리면 그 안의 주 버튼으로 포커스, 닫히면 게임 영역(`tabindex="0"`)으로 복귀. 오버레이는 `role="dialog"` + `aria-labelledby`, 게임판 뒤 요소는 열린 동안 `inert`.
- **키보드만으로 완전 플레이 가능**(시작·일시정지·재개·다시 하기 모두 키 제공). 조작 키 안내를 화면에 텍스트로 표시.
- **터치 대상**: 조작 버튼 56px 권장(최소 44px), 헤더 링크·토글 44px 이상. 각 버튼 `aria-label`("왼쪽으로 이동", "빠르게 내리기(누르고 있기)", "시계 방향 회전", "반시계 방향 회전", "바로 떨어뜨리기", "일시정지").
- **대비**: 텍스트 WCAG AA 4.5:1 이상(두 테마). 블록·그림자·격자는 비텍스트 대비 기준 **3:1 이상**(판 배경 대비) — 블록 색 7톤 모두 확인. 조각 구별은 색이 아니라 모양으로 가능하므로 색 의존 정보 없음.
- **움직임**: `prefers-reduced-motion: reduce` → 줄 삭제 번쩍임·사라짐 연출 끔(짧은 정지만), 오버레이 전환 애니메이션 끔.
- 일시정지 중 판 내용은 흐리게 가려서(블러 대신 반투명 덮개) 일시정지를 "생각할 시간"으로 악용하지 않게 함.

## 9. Embed 계획 (제안 — 별도 단계에서 진행)

> 이 단계에서는 블로그 파일을 수정하지 않습니다. 아래는 Embed 단계 담당자를 위한 제안입니다.

- 블로그 메인 카드는 `js/views.js`의 `APPS` 배열에 항목을 **추가**하는 방식입니다. 기존 `merge-tiles` 항목 뒤에 아래를 추가:

```js
{
  slug: 'stack-drop',
  title: '스택 드롭',
  description: '떨어지는 블록을 돌리고 쌓아 가로줄을 지우는 퍼즐. ↓를 누르고 있으면 빨리 내려가요.',
},
```

- 카드 이미지: `apps/stack-drop/preview.svg`(480×360). `renderAppCard`가 `apps/<slug>/preview.svg`를 쓰므로 파일명·크기 고정.
  - 미리보기 구성(안): 청록 계열 블록이 아래쪽에 들쭉날쭉 쌓인 판, 가운데쯤 떨어지는 조각 1개와 그 아래 점선 그림자, 맨 아래 한 줄이 밝게 빛나는 "삭제 직전" 행. 배경은 라이트 톤(카드가 두 테마 모두에서 자연스럽게 보이도록 둥근 사각 배경 포함). 글자는 넣지 않음.
- 링크: `apps/stack-drop/`(`index.html`). 별도 iframe 라이브 미리보기는 권장하지 않음 — 실시간 게임이 메인 페이지에서 키를 가로채거나 백그라운드에서 돌 위험이 있어서. 필요하면 머지 타일과 같은 "클릭 시에만 iframe 삽입 + `?embed=1`" 방식을 따름.
- Embed 단계에서 확인할 것: 카드 2개 이상일 때 `app-list` 레이아웃(모바일 1열, 넓은 화면 2열) 깨짐 없음.
