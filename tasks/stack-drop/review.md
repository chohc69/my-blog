# Review 서브에이전트 지침 — 스택 드롭 (stack-drop)

## 역할
너는 **Review 단계** 담당이다. Build 단계와 독립적으로 `apps/stack-drop/`의 구현이
승인된 기획서 `apps/stack-drop/spec.md`대로 동작하는지 검증한다.

## 수정 범위
- 생성: `apps/stack-drop/review.md` (검증 보고서)
- 문제를 발견하면 `apps/stack-drop/` 안의 코드(spec.md 제외)만 수정할 수 있다.
- 그 밖의 파일은 수정 금지. 커밋 금지.

## 사용자가 명시한 핵심 요구 (최우선 검증)
1. 블록 회전 (시계/반시계, 벽 차기)
2. **↓를 누르고 있는 동안 빠르게 낙하, 떼면 원래 속도 복귀** (키보드 + 모바일 ↓ 버튼)

## 검증 방법
1. **코드 리뷰**: `apps/stack-drop/` 전체. 버그, spec 불일치, 입력 상태가 꼬이는 경우(키를 누른 채 창 포커스 이탈, 일시정지 중 키 떼기 등), innerHTML 사용, localStorage try/catch, UI 문구에 "테트리스/Tetris"가 있는지.
2. **로직 테스트**: Node로 `js/game.js`, `js/input.js` 등 순수 모듈을 독립적으로 검증 (Build의 테스트를 재사용하지 말고 직접 작성). 임시 스크립트는 저장소 밖(OS 임시 폴더)에 두고 끝나면 삭제.
3. **브라우저 검증** (내장 브라우저 `mcp__Claude_Browser__*`, `http://localhost:8000/apps/stack-drop/`; 8000 서버가 이미 떠 있으면 재사용, 없으면 저장소 루트에서 띄우고 끝나면 종료)
   - **주의: 브라우저 창이 숨김 상태이면 requestAnimationFrame이 거의 돌지 않는다.** Build 단계는 이 때문에 실시간 동작을 못 봤다.
     이 경우 페이지 로드 후 javascript로 `window.requestAnimationFrame`을 가로채 큐에 쌓고, 가짜 타임스탬프(예: 16.67ms 간격)로 콜백을 수동 실행하는 스테퍼를 만들어 시간을 진행시켜라. 키는 `KeyboardEvent`(`code`) keydown/keyup을 dispatch한다.
     이 방법으로: 기본 중력 속도, ↓ 누르고 있는 동안 낙하 속도 vs 뗀 뒤 속도, DAS/ARR, 줄 삭제, 레벨 상승, 게임 오버 오버레이, 일시정지/재개를 실제 앱 코드 경로로 확인한다.
   - 콘솔 오류 0건, 라이트/다크, 375px·320px·데스크톱 폭, 가로 스크롤 없음, `?embed=1`
   - 모바일 버튼(포인터 이벤트 dispatch로 ↓ 누르고 있기 포함)
   - 스크린샷으로 화면 확인 (시작, 플레이 중, 게임 오버, 다크 모바일)
4. Build 보고의 확인 필요 항목: 격자선이 너무 진한지(가독성 판단 후 필요하면 조정, 결정 이유 기록), 모바일 판 높이 계산.
5. 블로그 본체(`http://localhost:8000/`)가 깨지지 않았는지 한 번 확인.
6. 테스트 중 넣은 `stack-drop:*` localStorage 값 정리, `theme` 키는 원래 상태로 복원. 화면 크기 에뮬레이션 해제.
