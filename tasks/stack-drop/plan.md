# Plan 서브에이전트 지침 — 스택 드롭 (stack-drop)

## 역할
너는 **Plan 단계** 담당이다. 웹앱을 구현하지 말고 **계획서만** 작성한다.

## 만들 웹앱
- 사용자 요청: "떨어지는 블록을 쌓는 퍼즐. 블록 회전 가능, 아래 화살표를 누르고 있으면 빨리 내려감."
- 위에서 블록 조각이 떨어지고, 좌우 이동·회전으로 쌓아 가로 줄을 채우면 그 줄이 사라지는 낙하 블록 퍼즐(장르 메커닉).
- **독자적인 게임으로 기획한다.** 특정 유명 게임(예: "테트리스")의 이름, 로고, 상징적인 배색(조각별 고정 색 세트), 음악, 화면 구성을 따라 하지 않는다.
  - 앱 이름: **스택 드롭 (Stack Drop)**. UI 어디에도 "테트리스/Tetris"를 쓰지 않는다.
  - 배색·블록 디자인은 블로그 테마에 맞춘 독자적인 스타일로 정한다 (참고: 이미 있는 `apps/merge-tiles/`는 인디고→바이올렛→마젠타 계열. 같은 블로그의 형제 앱으로 어울리되 구별되게).
  - 조각 세트(4칸 조각 7종을 쓸지 등), 회전 방식(벽 차기 포함 여부), 점수·레벨 규칙은 너가 결정하고 이유를 적는다.
- 필수 기능
  - ←/→ 이동, 회전(↑ 그리고 별도 키로 반대 방향 회전 권장), **↓ 누르고 있는 동안 빠른 낙하(소프트 드롭)**, 키 반복(DAS/ARR) 처리
  - 하드 드롭(Space) 권장, 다음 조각 미리보기, 일시정지
  - 줄 삭제, 점수·레벨·삭제 줄 수, 레벨에 따른 낙하 속도 증가
  - 점수판: 현재 점수, 최고 점수, 상위 기록(`localStorage`, `try/catch`)
  - 게임 오버 판정과 다시 하기
  - 모바일 조작: 화면 버튼(이동/회전/빠른 낙하 누르고 있기/하드 드롭) 및/또는 제스처
  - 라이트/다크 모드
- 게임 루프는 `requestAnimationFrame` 기반, 탭이 숨겨지면 자동 일시정지.

## 블로그 환경
- 정적 사이트, 프레임워크 없음. 테마: `<html data-theme>`, `localStorage`의 `theme` 키, `css/style.css`의 `:root` CSS 변수.
- 참고 구현: `apps/merge-tiles/`(spec.md, index.html, js/theme.js, js/storage.js 등)의 테마 처리, `?embed=1`, 저장 방식, 모듈 분리 패턴을 **읽기만** 해서 일관성 있게 따른다.
- 블로그 메인 카드는 `js/views.js`의 `APPS` 배열에 항목을 추가하는 방식이다 (Embed 단계에서 진행). 카드용 `preview.svg`(480×360)를 파일 구조에 포함한다.

## 웹앱 규칙
- 모든 파일은 `apps/stack-drop/` 안에 자체 완결. 블로그의 다른 파일을 건드리지 않는다.
- 외부 라이브러리 없이 순수 HTML/CSS/JS(ES Modules). 렌더링은 Canvas 또는 DOM 중 선택하고 이유를 적는다.
- 모바일에서 사용 가능 (375px 폭, 가로 스크롤 없음, 게임 영역 터치 시 페이지 스크롤·더블탭 확대 방지, 터치 대상 44px 이상).

## 산출물
`apps/stack-drop/spec.md` **한 파일만** 생성한다. 맨 위에 "사용자 승인 대기"라고 적는다.

포함 내용:
1. 개요와 게임 규칙 (조각, 회전, 낙하, 줄 삭제, 레벨·속도, 점수 공식)
2. 기능 목록 (필수 / 선택)
3. 조작표 (키보드, 모바일), 키 반복 타이밍 값
4. 화면 구성 (모바일·데스크톱, ASCII 스케치)
5. 파일 구조와 각 파일 역할
6. 핵심 로직 설계 (상태 구조, 충돌 판정, 회전/벽 차기, 랜덤 생성 방식, 고정(lock) 지연, 게임 루프 타이밍, 게임 오버)
7. 저장, 테마, 임베드 처리
8. 접근성
9. Embed 계획 (APPS 항목 문구 제안)
10. 테스트 체크리스트

## 완료 보고
핵심 결정 사항을 5~8줄로 한국어 요약.
