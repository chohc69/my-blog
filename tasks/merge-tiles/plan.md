# Plan 서브에이전트 지침 — 머지 타일 (merge-tiles)

## 역할
너는 **Plan 단계** 담당이다. 웹앱을 구현하지 말고 **계획서만** 작성한다.

## 만들 웹앱
- 사용자 요청: "방향키로 숫자 타일을 밀어서 합치는 퍼즐 게임 + 점수판"
- 4×4 격자에서 타일을 한 방향으로 밀면, 같은 숫자 타일이 부딪혀 합쳐지는(2의 거듭제곱) 슬라이드-합치기 퍼즐.
- **독자적인 게임으로 기획한다.** 기존 유명 게임(예: "2048")의 이름, 로고, 배색, 화면 구성을 따라 하지 않는다.
  - 앱 이름: **머지 타일 (Merge Tiles)** — UI 어디에도 "2048"이라는 이름을 쓰지 않는다.
  - 배색·타일 디자인·레이아웃은 블로그 테마(아래)에 맞춘 독자적인 스타일로 정한다.
  - 목표 타일 숫자는 고정 승리 조건 대신 다른 방식(예: 최고 타일 기록, 단계별 메달 등)을 고려해도 좋다. 결정은 너가 하되 이유를 적는다.
- 필수 기능
  - 키보드 방향키(+ WASD 권장) 조작, 모바일 스와이프 조작
  - 점수판: 현재 점수, 최고 점수(`localStorage`, `try/catch`로 감쌈), 가능하면 상위 기록 목록
  - 새 게임, 게임 오버 감지/표시, (선택) 되돌리기 1회
  - 타일 이동/합치기 애니메이션
  - 라이트/다크 모드 대응

## 블로그 환경 (조사 결과 요약)
- 정적 사이트, 프레임워크 없음. 루트 `index.html`은 해시 라우팅 SPA 셸(`js/app.js`, `js/router.js`, `js/views.js`).
- 테마: `<html data-theme="light|dark">`, `localStorage`의 `theme` 키. 색상은 `css/style.css`의 `:root` CSS 변수
  (`--color-bg`, `--color-text`, `--color-accent` 등). 라이트 accent `#4f46e5`, 다크 accent `#a5b4fc`.
- 필요하면 `index.html`, `css/style.css`, `js/*.js`를 **읽기만** 해서 참고한다.

## 웹앱 규칙 (CLAUDE.md)
- 모든 파일은 `apps/merge-tiles/` 안에 자체 완결. 블로그의 다른 파일을 건드리지 않는다.
- 외부 라이브러리 최소화 (CDN은 허용되지만 이 게임은 순수 HTML/CSS/JS로 충분할 것).
- 모바일에서 사용 가능해야 함 (375px 폭, 가로 스크롤 없음, 스와이프 시 페이지 스크롤 방지).

## 산출물
`apps/merge-tiles/spec.md` **한 파일만** 생성한다. 다른 파일은 만들거나 수정하지 않는다.

spec.md에 포함할 내용:
1. 개요 (한 문단)와 게임 규칙
2. 기능 목록 (필수 / 선택 구분)
3. 화면 구성 (모바일·데스크톱 레이아웃, 간단한 ASCII 스케치 가능)
4. 파일 구조 (`apps/merge-tiles/` 아래 각 파일의 역할)
5. 핵심 로직 설계 (상태 구조, 이동/합치기 알고리즘, 새 타일 생성, 게임 오버 판정, 점수 계산)
6. 테마 처리 방법 (블로그의 `theme` 키/`prefers-color-scheme`을 어떻게 따를지, iframe 임베드 시 포함)
7. 접근성 (aria-live로 점수/상태 알림, 포커스, 버튼 크기 44px)
8. Embed 계획: 블로그 메인(`index.html` / 글 목록 뷰)에 웹앱 카드(제목, 설명, 미리보기 이미지 또는 iframe)를 어떻게 넣을지 — 이 단계는 나중에 별도로 진행하므로 **제안만** 적는다.
9. 테스트 체크리스트 (Review 단계에서 확인할 항목)
