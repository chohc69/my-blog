# Build 서브에이전트 지침 — 머지 타일 (merge-tiles)

## 역할
너는 **Build 단계** 담당이다. 사용자가 승인한 기획서 `apps/merge-tiles/spec.md`를 그대로 구현한다.
(spec 상단의 "사용자 승인 대기" 문구는 이미 사용자 승인이 끝났으므로 무시한다. spec.md 자체는 수정하지 않는다.)

## 수정 범위 (엄격)
- 생성/수정 가능: `apps/merge-tiles/` 아래 파일 중 **spec.md를 제외한 것**
- 수정 금지: 루트 `index.html`, `css/`, `js/`, `posts/`, `CLAUDE.md`, `tasks/`, spec.md 등 그 밖의 모든 파일
- 블로그 카드 추가(Embed)는 하지 않는다. 나중 단계에서 따로 진행한다.
- 커밋하지 않는다.

## 구현 요구
- spec의 파일 구조, 상태 구조, 이동/합치기 알고리즘, 메달, 저장(`merge-tiles:` 접두사, try/catch), 테마(`theme` 키 공유, `?theme`, `?embed=1`), 접근성, 애니메이션을 모두 구현한다.
- spec의 "선택" 기능 중 1·2순위는 포함한다.
- 순수 HTML/CSS/JS(ES Modules). 외부 라이브러리·CDN 쓰지 않는다.
- UI 어디에도 "2048"이라는 이름을 쓰지 않는다.
- 코딩 스타일: 들여쓰기 2칸, 세미콜론, 작은따옴표, `const`/`let`만, 색상은 CSS 변수로.
- 모바일 375px에서 가로 스크롤 없음, 보드 위 스와이프 시 페이지 스크롤 방지, 터치 대상 44px 이상.
- `preview.svg`는 블로그 카드용 미리보기 이미지로, 게임 화면을 단순화한 독자적인 일러스트로 만든다.

## 자체 확인 (가능한 범위)
- `game.js` 순수 로직은 Node로 간단히 검증한다 (예: `node --input-type=module -e "import('./apps/merge-tiles/js/game.js')..."`로 이동/합치기 사례 몇 개). 검증용 임시 스크립트는 저장소 밖(OS 임시 폴더)에 두거나 끝나면 삭제한다.
- 브라우저 확인은 Review 단계가 하므로 필수는 아니다.
